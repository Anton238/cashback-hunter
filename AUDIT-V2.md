# Аудит и состояние переработки

## Исходное приложение

- React/Vite PWA, Cloudflare Worker + D1; записи группируются по категории, банку и месяцу. Данные кэшбэков, банки и синонимы находятся в D1, изображения — только в IndexedDB конкретного устройства.
- Просмотр трёх месяцев уже был; после 25-го числа автоматически выбирался следующий месяц. Существовали ручной ввод, локальный Tesseract OCR, справочники банков/категорий/синонимов, push-напоминания и ссылки на банки.
- OCR сопоставлял проценты и ключевые слова в одной строке и не извлекал условия. Аранжировщик принимал по одному файлу на банк, применял жадный алгоритм и не сохранял результат. Лимиты вводились на каждый запуск.
- Worker не проверял аутентификацию. CORS не защищает API от прямых запросов. До выпуска нового Worker существующий публичный API остаётся под прежними правилами.

## Новая версия

- Три месяца просмотра; запись — текущий или следующий. Ручная запись и по несколько фотографий на банк, последовательная проверка групп по банкам, ручное сопоставление/создание категорий, заметки, сохранение.
- Workers AI получает фотографии и возвращает предложения категорий; ответ является предположением, требующим проверки. Лимиты банков хранятся в D1. Распределение сначала максимизирует число покрытых категорий, затем сумму процентов; свободные места заполняются дубликатами. Базовый 1% Т-Банка показан отдельно, без расхода слота; условия карты нужно проверить.
- Push-напоминания можно включить, выключить и проверить на странице банков; расписание — последний день месяца. Исправления категорий для распознанных названий сохраняются по банкам и учитываются при следующих распознаваниях.
- Из исходных возможностей новый интерфейс пока не содержит управление синонимами и ссылки на банки; старые таблицы и маршруты сохранены. Старые фотографии не отображаются в новом интерфейсе и остаются в IndexedDB устройства. Отдельное редактирование сохранённой строки пока отсутствует: её можно удалить или перезаписать через добавление.
- Сохранение нескольких предложений выполняется по одному запросу, а не одной транзакцией: при ошибке уже сохранённые строки остаются в базе, интерфейс сообщает об этом.

## Безопасное развёртывание и ограничения

Пользователь выбрал временную публикацию без входа. API публичен: данные можно читать и менять. Ограничение запросов к AI не является защитой от доступа или всех злоупотреблений. Для приватности необходимо настроить аутентификацию. Не запускать старые инструкции DEPLOY.md без учёта этих шагов.

1. Сделать резервную копию D1 и проверить её восстановление. Для существующей базы один раз применить `worker/migrations/0001_cashback_v2.sql`. Затем применить `worker/migrations/0002_category_corrections.sql`. Для новой базы использовать обновлённый `worker/src/db/schema.sql`, не применяя к нему миграции повторно.
2. Настроить Cloudflare Zero Trust Access для приложения и API на одном origin, с политикой допуска только владельца. Настроить маршрутизацию `/api/*` на Worker и исключить обходные публичные маршруты; включить проверку подписи Access JWT в Worker через `ACCESS_TEAM_DOMAIN` (имя вида `team.cloudflareaccess.com`) и `ACCESS_AUD` (audience приложения). Без обеих переменных действует временный публичный режим; частичная настройка закрывает API. Проверить вход владельца, запрет постороннему и прямой доступ к workers.dev. Наличие заголовка без проверки подписи недостаточно. На pages.dev сама по себе маршрутизация `/api` на отдельный Worker не появляется: архитектуру origin/route надо настроить в аккаунте.
3. Подключить Workers AI binding, оставаться на Workers Free и проверить квоту. Используется Gemma 4 26B A4B через Workers AI. На синтетическом изображении распознаны русские категории, проценты и лимит; на банковских скриншотах и при исчерпании квоты модель ещё не проверена.
4. Настроить `FRONTEND_ORIGIN` и размещение фронтенда/API на одном origin; не помещать ключи в `VITE_*`, репозиторий, логи или URL. Скриншоты передаются Cloudflare для обработки; не загружать лишние личные данные.
5. Проверить миграцию на копии, сценарии на телефоне, сохранение и повторное открытие, а также уведомления/существующие данные до переключения production. GitHub Actions автоматически деплоит Worker при push в main/master, поэтому не отправлять незавершённые изменения в эти ветки.
